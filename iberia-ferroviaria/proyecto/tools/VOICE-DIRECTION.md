## Generar y publicar cuerpos completos

Desde `proyecto`, con Node 22 y el entorno Qwen activado:

```sh
source /workspace/tools/qwen-venv/bin/activate
npm run voice-dialogue-catalogue
npm run voice-dialogues -- --model /workspace/tools/qwen3-tts-0.6b --references ../investigacion/voces/referencias-qwen-3.6.3/prompts.json --catalogue ../investigacion/voces/dialogos-3.6.3.json --output ../investigacion/voces/generadas-qwen-dialogos-3.6.3-torrente --precision mixed-bf16-talker --batch-size 4 --seed 424242 --max-new-tokens 1024 --dry-run
```

El preflight no importa Torch ni genera audio. Verifica los 412 cuerpos contra los módulos actuales, los modelos fijados, las nueve referencias y la identidad aceptada de Pedro. Para inferir, conserva esos argumentos y sustituye `--dry-run` por `--generate`; para empaquetar, después de cerrar la producción y revisar los informes, sustitúyelo por `--package`. El proveedor exige una acción explícita y no combina generación con publicación. Se puede seleccionar un ensayo mediante `--clip`, o un pase inicial mediante `--max-priority`, pero la publicación exige el catálogo entero sin selectores y un manifiesto cerrado.

No cambies precisión, lote, semilla ni el eventual `--retry-seeds-file` entre reanudaciones y empaquetado. Las repeticiones con otra semilla se documentan por lote estable; no se decide repetir automáticamente por un error de ASR. Se conservan WAV, MP3, EOS, textos canónico y efectivo, condicionamientos, huellas y SHA. Las pruebas del proveedor usan audio sintético para comprobar corrupción, huellas, límites, recuperación y publicación; no ejecutan Qwen ni prueban la calidad de actuación.

La transcripción BASE es una evaluación separada. Este es el comando del comprobador para una instalación independiente; en la sesión actual ya está supervisado, por lo que no debe ejecutarse un segundo proceso:

```sh
/workspace/tools/voice-venv/bin/python tools/check_voice_transcripts.py ../investigacion/voces/generadas-qwen-dialogos-3.6.3-torrente --model /workspace/tools/whisper-base-http --watch --expected-count 412 --idle-timeout 3600 --output ../investigacion/voces/generadas-qwen-dialogos-3.6.3-torrente/transcript-qa-base.json
```

`asr-current-torrente/launch_base_current.py` liga el revisor supervisado al lanzamiento real del productor actual y recoge su código de salida real. La revisión usa los SHA actuales y conserva el literal primario, los finales, cifras y unidades, negaciones, rutas, instrucciones y posibles bucles. Los errores ASR no se aceptan, ocultan ni convierten automáticamente en repeticiones. Las ventanas focales o SMALL se ejecutan tras cerrar TTS y BASE, si una discrepancia importante lo requiere.
